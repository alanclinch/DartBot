# Handover — Cricket Enhanced-mode looks (Claude Design)

Read `CLAUDE.md` (repo root) first: project-wide context, **working principles**, and especially the
**Target environment** section (1080p TV, viewed at distance, screen glare, air-mouse control). This
work is purely visual, so that section is the design brief.

**Goal:** improve the looks of Cricket's **Enhanced (broadcast-TV) mode** by designing it in **Claude
Design** (https://claude.com/product/design) rather than hand-tweaking CSS blind. Claude Design can
import the repo so it works against the real components, let you iterate the board and winner screen
visually (prototypes, element edits, sliders), then round-trip the result back into the codebase via
the **DesignSync** tool / `/design-sync`. The refined output folds back into `assets/css/cricket.css`
(the `#game.enhanced-graphics` and `body.enhanced-winner` sections) and `drawEnhancedMarkSVG`.

## Why this is a handover (can't finish it in the current environment)
DesignSync needs an interactive `/design-login` to authorize against your claude.ai account, and this
environment doesn't provide one — the call fails with *"requires an interactive terminal and is not
available in this environment."* So the Claude Design / DesignSync leg is handed to the **Claude Code
desktop software**, where `/design-login` can complete the authorization. From there:

1. Authorize DesignSync (`/design-login`).
2. Create (or select) a design-system project named **"DartBot - Cricket Enhanced"**.
3. Push the enhanced components.
4. Iterate in Claude Design.
5. Sync back into `cricket.css` (+ `drawEnhancedMarkSVG` if mark rendering changes).

## The source is already prepared — `design/`
Two self-contained, **1920×1080** preview files, already committed and live on Pages:
- `design/enhanced-board.html` — the in-game 2-player board: topbar, player cards, cricket rows with
  lamp pips **in every state** (open / partial / closed / scoring / dead), central HUD/keypad.
  Live: …github.io/DartBot/design/enhanced-board.html
- `design/enhanced-winner.html` — the themed winner takeover (`body.enhanced-winner`).
  Live: …github.io/DartBot/design/enhanced-winner.html

They're generated by `design/build-previews.js`, which **inlines the real `game.css` + `cricket.css`**
so the previews can never drift from live styling. **Re-run `node design/build-previews.js` after any
CSS change.** They represent the *current* enhanced look as the baseline to redesign from, and carry
first-line `<!-- @dsCard group="Enhanced Cricket" -->` markers so Claude Design groups them under
**"Enhanced Cricket"**.

**Caveat:** the previews were hand-built to mirror the JS-rendered board and **have not been visually
verified in a browser** — eyeball them at 1080p first before trusting them as the baseline.

## Constraints for whatever comes back (don't lose these in the redesign)
- **Scoped:** everything must stay under `#game.enhanced-graphics` / `body.enhanced-winner` so that
  toggling **Enhanced Graphics off** reproduces **stock Cricket exactly**.
- **2-player only.**
- **Real target:** a 1080p TV viewed from across the room with window glare → **solid bright fills +
  dark text** (not subtle glows/translucency), **large legible type**, **air-mouse-friendly** controls.
- The **previous developer's design brief** (sun-lit constraints, broadcast aesthetic, end-game
  splash) also exists — **get it from the owner** and feed it into Claude Design.
